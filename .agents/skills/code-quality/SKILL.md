# Code Quality

- Analyze for real improvements in clarity, robustness, and maintainability.
- Prefer the simplest correct solution that matches existing style (flake8/pylint).
- If a superior alternative exists, choose the most production-solid one; state what improved and why.
- Do not break boot safety, SIP, FileVault, or existing patch contracts.
- Keep changes focused and measurable.
- Verify against existing code and configs.
- Note any remaining need for real Mac hardware validation.
